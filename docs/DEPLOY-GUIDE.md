# Как работает деплой Amalfi.Day Guide

> Гайд для Грега. Без лишней теории, только практика.

## Что такое трёхслойный деплой?

У нас три среды (environments). Думай о них как о трёх копиях сайта:

```
DEV (разработка)  →  STAGE (проверка)  →  PROD (боевой сайт)
```

| Среда | Для чего | Кто видит | Адрес |
|-------|----------|-----------|-------|
| **Dev** | Тестируешь новую фичу | Только ты | Случайный `*.vercel.app` URL |
| **Stage** | Финальная проверка перед релизом | Ты + кому покажешь | Случайный `*.vercel.app` URL |
| **Prod** | Настоящий сайт для пользователей | Все | `guide.amalfi.day` |

## Повседневная работа

### 1. Хочу поработать над новой фичей

```bash
# Создай ветку (имя — любое, только не main)
git checkout -b feature/новая-штука

# Делай изменения, потом коммить
git add .
git commit -m "Добавил новую штуку"

# Пуш — и через 2-3 минуты получишь ссылку на Dev-превью
git push origin feature/новая-штука
```

Где посмотреть ссылку:
- GitHub → Actions → последний запуск "Deploy Dev" → внизу будет URL
- Если есть Pull Request — бот напишет ссылку в комментарии

### 2. Фича готова — мержу в main

```bash
# Переключись на main
git checkout main

# Подтяни последнее
git pull origin main

# Смержи свою ветку
git merge feature/новая-штука

# Пуш в main = автоматический деплой на Stage
git push origin main
```

Или через Pull Request на GitHub (кнопка "Merge").

После пуша в `main` автоматически:
1. Прогонится линтер (проверка кода)
2. Если ок — соберётся и задеплоится на Stage
3. Ссылка появится в GitHub Actions

### 3. Всё проверил на Stage — выкатываю на боевой

```bash
# Создай релиз (версию увеличивай: v0.2.0, v0.3.0, v1.0.0...)
gh release create v0.3.0 --target main --title "Новые места и фиксы" --notes "Добавил 3 ресторана, починил карту"
```

Это запустит деплой на `guide.amalfi.day`. Через 3-4 минуты сайт обновится.

### 4. Удаляю ветку — Vercel сам подчистит

```bash
# После мержа — удали ветку
git branch -d feature/новая-штука
git push origin --delete feature/новая-штука
```

Dev-превью для этой ветки удалится автоматически.

## Как понять, на какой среде я смотрю сайт?

В левом нижнем углу будет цветной значок:

- **Зелёный** `DEVELOPMENT` — это Dev
- **Жёлтый** `STAGING` — это Stage
- **Ничего нет** — это Prod (боевой)

---

## Что где лежит

```
.github/workflows/
  deploy-dev.yml      ← деплоит ветки (кроме main)
  deploy-stage.yml    ← деплоит main
  deploy-prod.yml     ← деплоит при создании GitHub Release
```

Секреты (токены Vercel) хранятся в GitHub → Settings → Secrets → Actions. Их не нужно трогать, они уже настроены.

## Частые вопросы

### Я запушил, но деплой не начался?
Зайди в GitHub → Actions и посмотри, есть ли запуск. Если нет — проверь, что пушишь в правильную ветку.

### Деплой упал с ошибкой lint
Значит в коде есть ошибки ESLint. Запусти локально:
```bash
npm run lint
```
Почини ошибки (warnings — не критично, только errors), закоммить и запушь снова.

### Деплой упал при сборке
Запусти локально:
```bash
npm run build
```
Если и локально падает — чини. Если локально работает, а на CI нет — проверь, все ли файлы закоммичены (`git status`).

### Хочу посмотреть логи деплоя
```bash
# Последние 5 запусков
gh run list --limit 5

# Детали конкретного запуска
gh run view <ID>

# Логи упавшего шага
gh run view <ID> --log-failed
```

### Как откатить Prod?
Самый простой способ — создать новый релиз с предыдущего коммита:
```bash
gh release create v0.2.1 --target <sha-коммита> --title "Откат" --notes "Откат к предыдущей версии"
```

## Схема целиком

```
Ты пушишь в feature-ветку
        │
        ▼
  ┌─────────────┐     deploy-dev.yml
  │   DEV       │ ←── автоматически
  │ *.vercel.app│     на каждый пуш
  └─────────────┘

Мержишь в main
        │
        ▼
  ┌─────────────┐     deploy-stage.yml
  │   STAGE     │ ←── автоматически
  │ *.vercel.app│     линт → сборка → деплой
  └─────────────┘

Создаёшь GitHub Release
        │
        ▼
  ┌─────────────┐     deploy-prod.yml
  │   PROD      │ ←── автоматически
  │guide.amalfi │     линт → сборка → деплой --prod
  │    .day     │
  └─────────────┘
```

## Шпаргалка команд

| Действие | Команда |
|----------|---------|
| Новая ветка | `git checkout -b feature/название` |
| Пуш ветки (→ Dev) | `git push origin feature/название` |
| Мерж в main (→ Stage) | `git checkout main && git merge feature/название && git push` |
| Релиз (→ Prod) | `gh release create v1.0.0 --target main --title "..." --notes "..."` |
| Удалить ветку | `git push origin --delete feature/название` |
| Статус CI | `gh run list --limit 5` |
| Логи ошибки | `gh run view <ID> --log-failed` |
| Линт локально | `npm run lint` |
| Сборка локально | `npm run build` |
